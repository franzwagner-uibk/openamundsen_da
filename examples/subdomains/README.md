# Sub-domain Example (Rofental)

This setup is a sub-domain mode integration example for `oa-da-subdomain`. It supports both the data assimilation sub-domain workflow and the plain openAMUNDSEN model sub-domain workflow.

Layout:
- `subdomains.yml`: setup-level openAMUNDSEN config. It includes `start_date` and `end_date` so it can also be used directly by model sub-domain mode.
- `projects/project_2022_2023/project_2022_2023.yml`: project-level data assimilation config.
- `env/subdomains.gpkg`: non-overlapping ROI split into three sub-domains (`sd_01`, `sd_02`, `sd_03`).
- `grids/roi_<domain>_<resolution>.asc`: canonical ROI mask used by data assimilation (generated automatically from regions vector when missing).

Current data content:
- This setup now contains the same example data as `examples/rofental`:
  - grids: `grids/`
  - meteo: `meteo/`
  - raw snow-cover: `obs/snowcover/`
  - raw wet-snow: `obs/wetsnow/`
  - station observations: `obs/stations/`

Data assimilation workflow:
```bash
oa-da-subdomain pipeline \
  --setup-dir examples/subdomains \
  --project-dir examples/subdomains/projects/project_2022_2023 \
  --regions examples/subdomains/env/subdomains.gpkg \
  --max-workers 24 \
  --overwrite
```

Plain openAMUNDSEN model workflow:
```bash
oa-da-subdomain model-pipeline \
  --setup-dir examples/subdomains \
  --regions examples/subdomains/env/subdomains.gpkg \
  --max-workers 24 \
  --overwrite
```

Docker usage:
```bash
# Bundled example, run from the repository root
PROJ=./examples/subdomains docker compose run --rm oa \
  oa-da-subdomain model-pipeline \
  --setup-dir /data \
  --regions /data/env/subdomains.gpkg \
  --max-workers 24 \
  --overwrite

# Custom setup, run from the repository root
PROJ=/absolute/path/to/setup docker compose run --rm oa \
  oa-da-subdomain model-pipeline \
  --setup-dir /data \
  --regions /data/env/subdomains.gpkg \
  --max-workers 24 \
  --overwrite
```

`PROJ` is the host setup directory. Docker Compose mounts it as `/data`, so command-line paths inside the container should use `/data/...`. The image includes both `oa-da-subdomain` and the `openamundsen` executable used for each sub-domain run.

For a custom setup:
1. Replace `env/subdomains.gpkg` with the target sub-domain geometry.
2. Update paths in `subdomains.yml` to the target `grids` and `meteo` directories.
3. Keep `start_date` and `end_date` in `subdomains.yml` for model sub-domain mode.
4. Keep `--max-workers` at or below the CPU cores available to Docker/the host.
5. For DA runs, adapt the project YAML under `projects/` to the target data assimilation events, time span, and `obs` directories.

Minimal plain-model setup layout:
```
setup/
  <setup-name>.yml        # or setup.yml; plain openAMUNDSEN config
  env/
    subdomains.gpkg       # non-overlapping polygons with an id column, or pass --id-field
  grids/
    dem_<domain>_<resolution>.asc
    lc_<domain>_<resolution>.asc
    ...                   # any additional grids required by the setup
  meteo/
    stations.csv
    <station>.csv
    ...
```

The setup YAML must define the normal openAMUNDSEN domain settings (`domain`, `resolution`, `crs`, `timestep`, `timezone`), `start_date`, `end_date`, `input_data.grids.dir`, `input_data.meteo.dir`, and the desired `output_data` grid variables. `projects/` and `obs/` directories are not required for plain model mode. The `subdomains/model/` tree is generated by `model-prepare` or `model-pipeline`.

Default output behavior:
- `oa-da-subdomain merge` writes compact data assimilation grids to `projects/<project>/results/grids/da_output_grids.nc`.
- `data_assimilation.output.retention: compact` prunes heavy member grid artifacts after merge.
- Point outputs and point plots stay inside each sub-domain project directory.
- `oa-da-subdomain model-run` writes per-subdomain openAMUNDSEN outputs to `subdomains/model/<id>/results/`.
- `oa-da-subdomain model-run` writes per-subdomain diagnostics to `subdomains/model/<id>/run.log` and `subdomains/model/<id>/run_manifest.json`.
- `oa-da-subdomain model-merge` writes merged model grid outputs to `subdomains/model/results/grids/`.
- Model merge only handles matching grid outputs under each `<id>/results/grids/`; point/timeseries outputs are not merged in v1.
